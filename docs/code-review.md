# Code review and validation

The application-owned source files and build path were reviewed: startup/system services, Win32 window lifecycle, menus and resources, editor state and input, configuration, native documents, image decoding, and Vulkan resource/presentation handling. Bundled stb_image and nlohmann JSON were treated as dependencies, rather than rewritten.

| Area | Finding | Change |
| --- | --- | --- |
| Workspace rendering | Full-window Vulkan presentation competed with GDI child panels; the toolbar was a GDI emoji bitmap. This is consistent with the supplied transient-panel screenshots. | Removed floating/child workspace windows and toolbar rasterization. All client graphics and lettering share one Vulkan render pass, with sampled cel draws and one instanced chrome draw. |
| GPU selection | First suitable Vulkan device won enumeration order. | Explicit hardware ranking, NVIDIA discrete priority, feature/format/texture checks, device name in status, Optimus/AMD exports. |
| Presentation | Render-finished semaphore ownership followed frame slots. | Semaphores follow acquired swapchain image indices. |
| Paint uploads | Each update created staging allocations, submitted separately, and waited for queue idle. | Per-flight persistent mapped staging, copied into the same frame command buffer after its fence. |
| Swapchain rendering | Empty background render pass, image blit, and separate clear calls for every rectangle. | One graphics pass draws checkerboard, sampled cel textures with normal alpha blending, and instanced UI geometry; no canvas blit is needed. |
| Event loop | Minimized windows could retain a render request and spin; input draining could postpone frames indefinitely. | Minimized windows sleep, wake messages coalesce, input processing yields after 8 ms, interactive resize timer renders. |
| Documents | Arbitrary chunk lengths/dimensions allocated memory; partial trailing headers were accepted; saves truncated the destination. | Validate file/chunk bounds, dimensions, finite metadata and names; skip unknown chunks without allocating; replace via temporary file. |
| Document memory | Saving copied the image into a document and another pixel payload. | Stream the existing image separately from metadata, without those full-image copies. |
| Editing | No undo or unsaved-edit protection. | Tile-based stroke undo/redo, redo branching, dirty title, save/discard/cancel before replacement or close. |
| Image import | Decoding allocated pixels before editor size checks; PNG PPI probing reread the entire file. | Inspect dimensions before decoding; enforce limits; stream only PNG metadata headers. |
| Settings | Grid and measurements lived among many child edit controls. | Native Grid, Rulers, Image Settings, and New Canvas dialogs; strict numeric validation and unit conversion. |
| Rulers/grid | Rulers had no numbers; line generation scaled with document dimensions. | Adaptive labeled ticks, rotated vertical numbers, viewport-bounded grid generation and density thinning. |
| Startup/lifetime | Splash animation loading could continue after the editor opened; detached fullscreen menus leaked. | Keep the splash until clicked, stream at most three decoded frames, stop its loader on dismissal/shutdown; retain/reuse/destroy detached menu handles; clean partial Vulkan initialization. |

The workspace geometry is in `editor_ui.cpp`, with platform-independent render data. The same geometry is used by tests and the Windows Vulkan backend. The native dialog code remains in `app.cpp`; menu resources remain in `resource.rc`.

Version metadata now comes from `tools/generate_version.py`. Display strings retain the full `major.minor.YYYYMMDD.build` version. Windows fixed numeric versions encode the date as days since 2020-01-01 because their four fields are limited to 16 bits; file/product display strings retain the full date. Vulkan's packed version uses major/minor/build and its application name includes the complete display version. See Microsoft's [VERSIONINFO format](https://learn.microsoft.com/en-us/windows/win32/menurc/versioninfo-resource). `tools/verify_build.py` checks the executable's version resources, compiled display strings, debug flags, the shortened splash version prefix, both original embedded branding PNGs, their website URLs, the original first-frame poster and embedded MP4. It rejects old PNG sequence resources and hard imports of optional Media Foundation DLLs. The splash caches title measurements and both premultiplied logo bitmaps for [Win32 alpha compositing](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-blendfunction), retaining transparency over every animation frame.

The semaphore fix follows the [Khronos guidance on swapchain semaphore reuse](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html). NVIDIA's high-performance export follows its [Optimus rendering policy documentation](https://developer.download.nvidia.cn/devzone/devcenter/gamegraphics/files/OptimusRenderingPolicies.pdf); actual selection is performed by Vulkan device enumeration.

## Automated checks

- Windows x64 builds, including resources and embedded shaders; only `simp.exe` is emitted. Diagnostic builds replace the same executable.
- ASan/UBSan tests: every truncated prefix of a fixture document, extreme chunk lengths, NaN metadata, UTF-16 names, legacy documents, unknown chunks, successful and failed replacement saves, overlapping undo tiles, partial edge tiles, redo branching, and 1,000 steps without eviction, low resident pixel-history memory, and undo/redo of guide creation, moves, styles, and deletion.
- Workspace tests: 1280×720, 1740×937, 3200×1800; scales 1, 1.25, 1.5, 2 subject to window fit; all three units; rulers on/off; fit and maximum zoom; dense grids; rectangle bounds and nonoverlapping click targets; PPI changes preserve pixels and pixel-space grid spacing.
- glslang compilation and `spirv-val` for Vulkan 1.1 graphics and compute modules.
- CPU SIMD paths, misaligned buffers and tails, all-color inventory across the small/large-image threshold, concurrent copy-on-write snapshots, nested pool jobs and exception propagation.
- Cel sanitizer tests: source-over compositing/sampling, names/order/visibility/active selection, single-preview payload reuse, malformed chunks, cross-cel painting and structural undo, and clearing sessions with queued journal writes.
- Headless cel graphics execution on SwiftShader (test only): alpha blending, stacking order, hidden cels, checkerboards, nearest sampling and transformed/scissored image rectangles.
- Headless compute execution on SwiftShader (test only): BGRA and alpha bytes, overlapping updates and workgroup edges match the CPU reference. This does not execute the Win32 backend or measure RTX performance.

## Target-machine validation still required

This build environment cannot run the Win32 window or inspect the user's NVIDIA adapter. Run the final executable on Windows and verify:

1. Toolbar, tools, palette, and rulers appear on the first frame and remain visible through expose, resize, minimize/restore, maximize, fullscreen, and monitor/DPI changes.
2. The status bar names the NVIDIA GPU on a hybrid system. Check another GPU-only system for the documented hardware fallback. No software renderer should be accepted.
3. Build with `./build.sh debug` and run `simp.exe` with Vulkan validation enabled externally; exercise repeated painting and resize/minimize cycles. Confirm no synchronization or lifetime errors.
4. Paint, sample colors, pan, zoom at the pointer, undo/redo, save/reopen a document, and cancel close/open/new with unsaved work.
5. Check ruler measurements at known pixel positions: 100 pixels at 100 PPI is one inch or 2.54 cm. Change PPI and confirm pixel dimensions and painted details are unchanged.
6. Check Grid dialog unit conversions, all numeric limits, PPI, and New Canvas on the target GPU's texture limit.
7. Double-click both rulers to create lines, drag markers outside their rulers and beyond the window while holding the button (movement must continue on the original axis), release to finish, right-click for color/thickness/Delete, toggle LINES/RULERS, and undo/redo these changes. Verify the glow stays inside each ruler at all zoom and DPI settings.
8. Check the exact File menu order, individual Open filters, Ctrl+S direct saves, Save As, and cancellation. Export PNG with each filter/interlace combination, reopen it, and compare every RGBA pixel and PPI (allow the PNG integer pixels-per-meter rounding). Confirm export does not change the document's Save destination.
9. Check `v.` and the current version at the upper left, the raised title with heavier lowercase text, 15% smaller Vulkan artwork, taller/narrower title lettering, lighter uncut shadows, and Lakeshore artwork with its caption above. Hover both caption/logo blocks for the hand cursor and click each to open the correct website in the default browser (restart between clicks). Leave the splash open for at least a minute. Keyboard input and clicks outside it must not dismiss it. Click the splash to dismiss it; close the application while it is open and confirm its worker stops cleanly.
10. Open a large, many-color image and exercise pan/zoom/menus during decode and save. Edit again while a save is running: the dirty mark must remain for newer edits. Close with Save while another completion is ready; no nested-pump deadlock should occur. Try rapid Open/New changes to check stale completion/frame rejection.
11. Verify BRUSH starts at one image pixel and grows/shrinks with the wheel, Ctrl+wheel still zooms, strokes stay connected during fast motion and stop bridging when the pointer leaves/re-enters the image. Check edge clipping and undo/redo after resizing and after switching tools mid-drag.
12. Hold/release Alt with BRUSH, CELL and PICK: only the active swatch should glow in its own exact color. Paint and sample both colors, Alt-click palette entries and picker swatches, and switch focus or open a native dialog while Alt is held. Confirm the primary color returns on release/focus loss. Check button label centering, original-size, dimmer ruler text, HEX/RGB/HSV values and the removed Image Settings workspace button at all DPI settings.
13. On a compute-capable NVIDIA GPU, compare a saved/reopened painted image with the presented canvas after overlapping fills, undo/redo, resize, and repeated document replacement. Check that ORIGINAL shows exactly 100% and palette scrolling reaches rare colors. Compare input and frame times with GPU validation disabled for performance measurements.

Rendering now uses the hardware graphics pipeline throughout the client area. Brush and cell painting additionally use capability-gated Vulkan compute; decoding and a lossless reference image remain on the CPU. Input and GPU submission run on separate threads; decode, palette work, save/export and canvas creation run on CPU workers. Undo/redo reads/application and reference-pixel edits still involve the window thread; completed journal writes use their own serial worker; see [performance details](performance.md). Real frame times, input latency, hybrid-GPU behavior, crash/power-loss durability, and throughput still require target-machine measurements. Temporary-file replacement protects against ordinary failed writes; it is not an autosave or recovery system.

The `.smp` extension change was conditional. It is retained as `.simp` because [XnView lists the Xionics SMP image format](https://www.xnview.com/en/image-formats/). Guide definitions use an optional `GLNS` chunk so older documents and readers remain compatible. Undo history uses a separate, automatically removed session journal with no fixed eviction limit; it is not part of `.simp` and does not provide cross-session recovery.

PNG export uses the [WIC PNG encoder's filtering and interlace options](https://learn.microsoft.com/en-us/windows/win32/wic/png-format-overview) and its native straight-alpha BGRA input. It writes scanlines directly, avoiding a full-image bitmap/converter copy. Native WIC encoding and mouse-driven dialogs still need execution on Windows; Linux sanitizer tests do not exercise COM codecs or Win32 input delivery.

## Native theme and cels validation

Native menu items retain their command IDs and text, with owner-drawn backgrounds, labels, separators and checks using `EditorTheme`. Dialog subclasses handle native control backgrounds, button painting and the application's owner-drawn unit/filter combo boxes. Keyboard, focus, selection and button notification handling remain with Windows. Brushes, menu metadata and DPI-specific fonts are cached and released after windows are destroyed. See Microsoft's [owner-drawn menu documentation](https://learn.microsoft.com/en-us/windows/win32/menurc/using-menus), [SetWindowTheme](https://learn.microsoft.com/en-us/windows/win32/api/uxtheme/nf-uxtheme-setwindowtheme), and [common-dialog customization](https://learn.microsoft.com/en-us/windows/win32/dlgbox/customizing-common-dialog-boxes).

Windows shell dark-mode opt-in also uses optional UXTheme exports, guarded by OS version and export availability. These are undocumented and may change; application menu/control painting does not depend on them. Microsoft's [PowerToys ZoomIt utility](https://github.com/microsoft/PowerToys/blob/main/src/modules/ZoomIt/ZoomIt/Utility.cpp) uses this process-local approach. Shell-owned controls and title frames may differ between Windows versions. The implementation does not alter the user's global Windows theme.

Additional target-machine checks:

- Open every application dialog, MessageBox, file chooser and color chooser. Check dark backgrounds, muted text, disabled controls, selected combo rows and default/focused buttons. Use Tab, arrows, Space, Enter, Escape, F10 and menu mnemonics; verify Alt color selection still resets correctly after menus/dialogs. Repeat across DPI changes and Windows versions.
- Open `example.simp`; select each cel, toggle visibility, rename, duplicate, add a transparent cel, paint on it, reorder and delete. Undo/redo across cel switches and structural edits. Save/reopen and verify pixels, names, order, visibility and active selection. Export PNG and compare the visible composite, including transparent areas with all cels hidden.
- Confirm `config.json` records the exact absolute file path after Open, Save and Save As. Restart with both native documents and imported images, including Unicode paths. Remove or rename the remembered file and verify an error plus a usable new canvas. Unsaved work and undo history are not restored across sessions.
- Repeatedly select/hide/reorder cels while painting, saving, resizing and minimizing with Vulkan validation enabled. Check that queued brush commands reach their original cel and descriptor/image lifetimes remain valid. Measure texture rebuild and large structural undo costs on the actual GPU.

## Compressed splash validation

`tools/encode_splash.py` validates contiguous source numbering, PNG dimensions and source hashes, then verifies H.264 High profile, 1280×720, 30 FPS and all 141 frames with ffprobe. It packages the MP4 and first original PNG only. The build verifier compares both assets with the PE resources and confirms that missing optional Windows media DLLs cannot prevent EXE loading. The complete MP4 was decoded on Linux and checked against the source sequence in BT.709/4:2:0 space; this checks the encoded asset, not the Windows decoder. Sanitizer checks exercise top-down/bottom-up and padded RGB32 row handling, invalid buffer footprints, and shadow opacity, smooth falloff and padding.

On Windows, check playback orientation, color, sharpness and smooth looping for several minutes. Click both branding links on separate launches, dismiss immediately during decoder startup, and close the app with playback active. Confirm no hang, use-after-free or leaked media session. Verify the static poster fallback on Windows N without the Media Feature Pack (or a debugger-induced decoder initialization failure); links and click dismissal must still work. Check the smaller logo blocks, condensed title and fade boundaries at native splash size over both bright and dark animation frames. These native decoder/GDI behaviors cannot be executed by the Linux sanitizer suite.
