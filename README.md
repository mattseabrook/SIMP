# SIMP

SIMP (Simple Image Manipulation Program) is a Windows x64 image editor with a compact DeluxePaint-inspired workspace in dark charcoal tones: beveled controls, a fixed tool strip, a color palette, and labeled rulers. It edits BGRA raster cels with pixel-brush and grid-cell paint tools, preserving their independent pixels in `.simp` documents.

Build with `./build.sh release` or `./build.sh debug`, then run `simp.exe` on Windows. Both build modes produce that single executable. The cross-build needs Clang, lld-link, MinGW windres, Python 3, FFmpeg/ffprobe with the libx264 encoder, glslangValidator, the Windows SDK under `/opt/winsdk`, and Vulkan SDK headers/libraries under `/opt/VulkanSDK/1.4.313.2`. Shaders compile and embed at build time; runtime shader tools and sidecar shader files are unnecessary. Vulkan 1.1 hardware is required.

One generated header supplies the splash, About dialog, Windows file/product version strings, and Vulkan application metadata. The build verifies those strings, both embedded branding PNGs, splash hyperlinks, the compressed video and original poster, and the absence of the old PNG animation resources.

The splash shows `v.` and the version in the upper-left corner, with taller, narrower Arial title lettering and heavier lowercase text. “Powered by” sits above the Vulkan logo on the lower left; “Authored by” sits above the supplied Lakeshore Technical logo on the lower right. Both branding blocks are displayed 15% smaller than before; source PNGs remain unchanged. Text and logos have lighter, wider Gaussian shadows, with additional window-edge padding for an uninterrupted fade. Each complete caption/logo block has a hand cursor and opens its website in the default browser: [Vulkan](https://www.vulkan.org/) or [Lakeshore Technical](https://www.lakeshoretechnical.com/). It stays visible until clicked on the splash itself, or until the application closes. There is no dismissal timer, keyboard shortcut, or outside-click hook.

The 141 original 1280×720 PNG frames are read-only build inputs. `tools/encode_splash.py` packages them as one embedded 30 FPS H.264/MP4, using CRF 12, animation tuning and explicit BT.709 color metadata for a perceptually lossless target. H.264 remains lossy and uses 4:2:0 chroma; visual equivalence is not a mathematical guarantee. Encoded output is cached by source/settings/content hashes under `build/generated`; FFmpeg is a build tool and is not distributed with the editor. The resulting executable is about 6.2 MiB instead of 69 MiB.

Playback uses Windows Media Foundation from an in-memory stream on the splash's dedicated COM worker, with at most three queued frames. Optional media DLLs are loaded at runtime, so missing Windows media components or a decoder error leave the original first-frame PNG/last decoded frame visible with working links and dismissal. No video file is extracted to disk. The native splash currently uses CPU-visible RGB32 frames and GDI compositing; this is separate from the Vulkan editor workspace and does not claim zero-copy GPU video decoding.

## Workspace and controls

The main client area, including panels, buttons, palette, lettering, grid, rulers, lines and their glows, is rendered entirely through Vulkan. Windows supplies the title frame, menu bar, modal settings and file dialogs, and a separate click-to-dismiss startup splash. There are no GDI-painted workspace panels or toolbar bitmaps. Native menus and application dialogs use the same charcoal palette, muted text, amber highlights and beveled controls. Native file/color dialogs receive the process-local dark theme too; Windows-owned shell regions can vary with the Windows version. No system-wide theme settings are changed.

- **BRUSH [B]** paints a square brush starting at one image pixel. With BRUSH selected, the wheel changes its size by one pixel per notch (1–1024); Ctrl+wheel still zooms. The current size appears beneath the tools. **CELL [C]** paints grid cells; **PICK [I]** samples image colors. Dragged strokes interpolate between pointer events; straight brush runs merge into fills and overlapping large stamps paint only their exposed strips.
- The right-side **PICKER**, below CELS, has primary and secondary swatches. Click either for the native color chooser. The primary swatch glows in its own color; holding Alt moves the glow to the secondary. Brush and cell painting use the active color. Palette clicks and PICK sampling set the primary color normally, or the secondary while Alt is held. Alt-clicking either picker swatch edits the secondary color. Release Alt to return to the primary color. The active color is shown as HEX, R/G/B (0–255), hue in degrees, saturation and value (percent). Painting is currently opaque; these values describe RGB paint, rather than file alpha.
- Vulkan workspace text uses its original size, button labels and the TOOLS heading center on their visible glyphs, and ruler labels use a dimmer color. Image Settings remains available through the Options menu.
- **ORIGINAL**, between + and FIT, shows one image pixel per physical screen pixel (100%), independently of image PPI and Windows display scaling.
- The PALETTE is a black well containing flat squares for every distinct RGB color stored across all cels, including hidden cels. There are no starter colors, sampled subsets, or color-count caps. Alpha variations share a paint color. Larger inventories use smaller squares and scroll with its scrollbar, or with the wheel over the palette when CELL or PICK is selected; drawing cost follows the visible area. Analysis refreshes after a stroke or pixel undo/redo.
- Right-drag pans the viewport. Ctrl+mouse wheel zooms around the pointer. Fit or Ctrl+0 resets zoom and pan; Ctrl++ / Ctrl+- zoom around the workspace center.
- Edit > Undo / Redo, Ctrl+Z, Ctrl+Y, and Ctrl+Shift+Z work on painting, line changes, and cel creation, duplication, deletion, naming, visibility and ordering. There is no fixed history step or byte cap. Completed actions write to a temporary disk journal on a separate serial I/O worker; the active stroke captures touched 64×64 tiles. Available storage and memory remain physical limits. History is session-only and resets when another document is opened or created; it is not embedded in saved documents.
- File > New (Ctrl+N) sets up a new canvas. Open (Ctrl+O) opens a document or imports an image, with separate named file-type filters. Save (Ctrl+S) writes directly to the current document; an untitled/imported image first asks for a native document path. Save As (Ctrl+Shift+S) chooses a different destination. Closing or replacing modified work offers Save, Discard, or Cancel.
- Native `.simp` files remain editable. Imported PNG physical-resolution metadata is used when available. New canvases and imports support up to 64 million pixels, at most 16,384 per axis, further limited by the selected GPU. Documents support up to 1,024 cels within an aggregate 268,435,456-pixel allocation limit (one GiB of cel pixels, excluding previews, history, snapshots and GPU copies).

## Cels

**CELS** is below PALETTE on the right. The top row is the topmost cel. Click a name to select the cel to paint; click **V** / **-** to show or hide it. **NEW** adds a transparent cel above the active one, **DUP** duplicates it, **DEL** removes it (the last cel is retained), **NAME** renames it, and **UP** / **DOWN** change its stacking order. Use the scrollbar for longer lists, or the wheel over the list with CELL or PICK selected. BRUSH keeps its wheel-size shortcut. A hidden active cel cannot be painted.

Visible cels composite with normal source-over alpha; transparent areas show a checkerboard. PICK samples the visible composite. PNG export composites only visible cels and preserves the resulting transparency. Each cel has the same pixel dimensions and shares the document PPI, grid and guides. Animation frames, alternate blend modes, per-cel offsets and opacity controls are future features.

[example.simp](example.simp) is a 320×240 retro city scene with three independent cels: Night sky, Sun and skyline, and Neon ink. Open it and toggle or paint each cel to try the implementation. `tools/create_example.cpp` reproducibly generates it using the native writer.

The optional `CELS` / `CELD` chunks store cel IDs, names, order, visibility, active selection and original BGRA pixels. The outer SIMP format version stays at 1; the cel chunk revision is 2. A normal `LAY0` composite remains for older readers, which can display it but cannot preserve separate cels when re-saving. A single visible cel reuses that preview payload instead of duplicating its pixels. Older single-image `.simp` documents open as one editable cel.

## Options

The native menu order is **File, Edit, Options, View, Help**.

**Options > Grid…** sets cell spacing in pixels, inches, or centimeters, major-line frequency, and visibility. Spacing is at least one image pixel and also controls the paint cell size. Dense grid lines are thinned below four screen pixels to keep drawing cost proportional to the viewport.

**Options > Rulers…** selects **Pixels**, **Inches**, or **Centimeters**, and ruler visibility. Tick spacing adapts to zoom; vertical labels rotate to preserve complete measurements. Inches use image PPI; centimeters use PPI / 2.54 pixels per centimeter.

**Options > Image Settings…** sets pixels per inch. PPI changes physical measurements without resampling pixels; the canvas, grid, and offsets retain their positions in image pixels. New Canvas sets pixel width, pixel height, and PPI separately.

**LINES** toggles ruler guide visibility independently of GRID and RULERS. Double-click the top ruler to add a vertical line, or the left ruler to add a horizontal one, at the pointer's document position. Start a left-drag on a line marker inside its ruler to move it along that axis. Once grabbed, it follows the pointer even outside the ruler or window until the button is released; dragging a line does not paint the image. Right-click a marker in the ruler for a nearby native dialog with thickness (image pixels), color, and Delete. Only the highlighted marker has a color-matched glow, blended inside its ruler. Hit testing allows 12 logical pixels on either side; the soft glow extends 18 logical pixels. Lines are nondestructive guides and are saved with the document.

**File > Export to PNG…** opens a native export dialog for the destination, adaptive/none lossless filtering, and interlacing. Export writes the visible cel composite as 8-bit RGBA pixels and PPI, preserving transparency; guides, rulers, and grid stay out of the PNG. It uses the existing Windows Imaging Component encoder, adds no image-library dependency, and replaces the destination only after encoding succeeds. Import continues to use stb_image.

`config.json`, beside the executable, stores workspace settings, window placement and `lastOpenFile`: the absolute UTF-8 path of the last successfully opened file or saved document. Startup opens that exact file, including an imported image. If it is missing or invalid, the app reports the error and opens a blank canvas. This restores the saved file, not unsaved changes; creating an untitled canvas does not replace the remembered path. Old floating-panel coordinates are ignored. `.simp` documents preserve separate cels, PPI, grid settings, ruler units, and line definitions; older documents remain readable. Configuration and document saves replace their destination through a temporary file after a successful write.

## Vulkan implementation

SIMP enumerates compatible hardware GPUs and prioritizes **NVIDIA discrete**, then other discrete, then integrated GPUs. Device-local memory and maximum texture dimensions rank candidates within a category. Software/CPU Vulkan devices are excluded. NVIDIA Optimus and AMD high-performance exports are included. The status bar shows the actual selected device; an unavailable or incompatible NVIDIA adapter cannot be selected.

The renderer uses Vulkan directly: device-local cel textures, nearest-neighbor sampled cel draws with hardware alpha blending, and one instanced graphics draw for workspace geometry, text, and alpha-blended line glows in the same render pass; reusable CPU geometry and hit-target buffers, two frame slots, and one presentation semaphore per swapchain image. Dirty pixels upload through reusable mapped buffers in the frame submission. Painting does not allocate staging memory or wait for queue idle on every stroke update once buffers have reached the needed capacity. Image replacement, swapchain recreation, and shutdown still synchronize resource lifetime explicitly. Idle and minimized windows do not render continuously.

The Win32 input/window thread runs at above-normal priority. A separate above-normal Vulkan thread owns every mutable Vulkan object, submission, fence wait, and presentation. Immutable frame packets coalesce; pixel/paint commands retain their order and document generation. Image load/decode, canvas/cel creation, exact-color analysis, native saves, and PNG export run on a shared, sleeping CPU pool (up to eight normal-priority workers). Save/export snapshots share pixels until an edit needs its own copy. Revision checks prevent a completed older save from marking newer edits clean. Cel selection and visibility changes send metadata commands without re-uploading the stack. Paint/upload commands retain their target cel even when selection changes before presentation. PNG and compatibility-preview compositing runs on CPU workers; displayed cels composite directly on the GPU.

Brush and cell fills dispatch a Vulkan compute shader directly into the device-local canvas when BGRA storage writes, format feature flags, and compute queues are supported. The renderer checks and enables the required capabilities; other supported hardware retains the upload path. A CPU pixel reference is still maintained for lossless documents, exports and undo. CPU fills and channel conversion use runtime-selected AVX2 with an SSE2 baseline; large ranges run in parallel without spawning per-operation threads. Small work stays inline.

The window thread still performs input/layout, touched-tile capture, CPU paint bookkeeping, copy-on-write detachment when readers are active, and undo/redo reads and application. Completed history writes run on the dedicated I/O worker, independently of decode/palette jobs. This is not a claim that the entire editing/codec pipeline has moved to the GPU. There is no selection tool or export format beyond PNG and the native document yet. No speedup against another editor has been benchmarked. See [threading, GPU terminology, and remaining performance work](docs/performance.md).

## Verification

Run `./tests/run.sh` on the Linux build host. It checks one-pixel and resized brush coverage, clipping, connected strokes, fill merging, secondary-color undo/redo, centered button glyphs, picker glow colors, document roundtrips, legacy/unknown chunks, malformed and truncated files, save replacement, 1,000-action disk-backed undo/redo, line persistence, ruler hit testing and glow clipping, and the actual workspace geometry across sizes, DPI scales, ruler units, and zoom limits. Tests run with AddressSanitizer and UndefinedBehaviorSanitizer; leak detection is disabled because this managed runner disallows the required ptrace access. All five SPIR-V modules are compiled and validated. CPU tests compare SIMD paths and unaligned tails, inventory every color (including rare last pixels), isolate concurrent snapshots, and exercise nested parallel jobs.

For a headless Vulkan shader execution check, set `SIMP_TEST_VULKAN_ICD=/path/to/icd.json ./tests/run.sh`. These optional checks compare compute BGRA bytes, all alpha values, overlapping edits and dispatch edges against a CPU reference, and execute the actual cel graphics shaders to verify order, visibility, alpha blending, checkerboards, nearest sampling and clipping. Cel sanitizer checks cover metadata/pixel roundtrips, preview reuse, malformed data, cross-cel/structural undo and session cancellation during queued journal writes. A software test ICD is allowed only in this test; production GPU selection still rejects software devices.

See [the code review and Windows validation notes](docs/code-review.md). Cross-build and geometry tests do not substitute for running the Win32 swapchain on the target NVIDIA system.

The `.simp` extension is retained: `.smp` is already used by image formats, including [Xionics SMP](https://www.xnview.com/en/image-formats/).

For a future splash typeface change, **Barlow Semi Condensed SemiBold** is the recommended option: stronger lowercase strokes and a narrower face for the full application name. It is distributed under the [SIL Open Font License](https://github.com/google/fonts/blob/main/ofl/barlowsemicondensed/OFL.txt). This build keeps the existing system Arial family with condensed title proportions and heavier lowercase weight; no additional font install or font asset is required.
